# Reusable Building Blocks

**Principle:** assemble products from shared, reusable components — technical and knowledge-based.

## Why

Reuse lowers cost, raises consistency, and compounds over time. A growing library of building blocks is a large part of "delivery as an organizational capability."

## Kinds of building blocks

- **Technical components** — services, connectors, UI patterns, pipelines.
- **Knowledge blocks** — validated prompts, narrative/reporting models, domain rule sets.
- **Reference artifacts** — canvases, patterns, and templates.

## How

- During Design, check what already exists before building new.
- Prefer composing blocks over bespoke work.
- When you build something reusable, register it so others can find it.
- Track block behavior so reuse is safe (a block with unknown behavior is a risk).

## Relationship to other principles

Reusable building blocks depend on [Knowledge First](knowledge-first.md) and enable [Reference-Driven Delivery](reference-driven-delivery.md).
