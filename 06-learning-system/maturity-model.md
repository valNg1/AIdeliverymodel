# Maturity Model

A simple way to assess how developed an organization's delivery capability is. This is a first version — the levels are indicative and meant to prompt honest conversation, not to score precisely.

## Dimensions to assess

- **Business First** — are choices driven by business value?
- **Ownership** — does every product have a single accountable owner?
- **Human + AI team** — is AI used in defined roles with human validation?
- **Knowledge & reuse** — is knowledge captured and reused; are building blocks growing?
- **AI-native Discovery** — is Build and Run impact surfaced before commitment?
- **Product Operations** — is the Run planned, owned, and supervised? *(experimental)*
- **Continuous learning** — does each delivery improve the capability?

## Indicative levels

| Level | Name | Signal |
|---|---|---|
| 1 | Ad hoc | Projects, dispersed accountability, Run unplanned |
| 2 | Emerging | Some products owned; Discovery used inconsistently |
| 3 | Established | AI-native Discovery standard; canvases and ownership in place |
| 4 | Operated | Run planned and supervised; references and reuse compounding |
| 5 | Capability | Delivery is a deliberate, measured organizational capability |

## How to use it

- Assess honestly; the point is direction, not a grade.
- Product Operations is experimental, so expect lower maturity there and record open questions in the [research backlog](../05-product-operations/research-backlog.md).
- Reassess periodically and connect findings to [continuous learning](continuous-learning.md).
