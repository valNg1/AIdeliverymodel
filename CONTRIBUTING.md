# Contributing to the AI Delivery Model

Thank you for helping improve this framework. It is a living, documentation-only project: contributions are ideas, clarifications, templates, and field-tested improvements — not code (at this stage).

## Ground rules

- **Keep it generic.** Do not include confidential or identifiable information about any specific organization. Use generic company examples only.
- **Do not invent evidence.** Do not add metrics, results, or case-study outcomes that were not actually observed. If something is a hypothesis, label it as one.
- **Mark unstable areas.** If a practice is not yet stabilized (for example, parts of Product Operations / Run), present it explicitly as experimental.
- **English first.** Write primarily in English so the framework stays shareable internationally. A short French summary in the README is welcome.
- **Simple Markdown.** Use plain, readable, GitHub-compatible Markdown. Avoid unnecessary jargon.

## How to contribute

1. Open an issue describing the change and the problem it solves.
2. For text changes, submit a pull request with a clear, focused diff.
3. Keep each pull request scoped to one topic where possible.

## Style guide

- Prefer short sentences and active voice.
- Use relative Markdown links between files in this repository, and check that they resolve.
- Keep terminology consistent with [glossary.md](glossary.md). If you introduce a new term, add it there.
- Do not leave files empty. A short but useful first version is always better than a placeholder.

## Review and validation

Consistent with the model's own principles: proposals are analyzed openly, but a human maintainer builds consensus and makes the final decision on what is merged.
