# From Buy to Make

## The historical model

For roughly two decades, the rational default was:

- **Buy** packaged software.
- **Outsource** its integration to vendors and system integrators.
- **Run each initiative as a project** that ends on delivery.

This made sense when producing software was slow and costly. It also produced predictable downsides: fragmented systems, thin internal knowledge, and dependence on external integrators for anything strategic.

## What AI changes

AI lowers the cost of producing software. When production is cheaper, the calculus shifts:

- Strategic products that were once too expensive to build in-house become feasible to build and own.
- Commodity needs — where there is no differentiation to protect — are still best **bought**.

The decision is no longer "buy by default." It is a deliberate **build-vs-buy** choice per capability.

## A simple decision lens

| Question | Lean Buy | Lean Make |
|---|---|---|
| Is this a source of differentiation? | No | Yes |
| Does a good commodity product already exist? | Yes | No / poorly fitting |
| Do we need to own the data, logic, and evolution? | No | Yes |
| Is the total cost of ownership dominated by Run? | Either | Consider Make + strong Run plan |
| Do we have (or want) the capability to operate it? | No | Yes |

This is a lens for structuring the conversation, not a scoring formula. Use it inside Discovery, where Build and Run impacts are made visible.

## The real shift: the asset is the capability

The most important consequence is not any single product. It is that the **strategic asset becomes the organization's capability to produce, operate, maintain, and evolve digital products** — repeatably.

That capability is what the rest of this framework is designed to build:

- an [operating model](../01-operating-model/overview.md) and lifecycle;
- an [AI-native Discovery](../02-ai-discovery/overview.md) that connects need to Build and Run;
- [delivery practices](../03-delivery/) built on knowledge, references, and reuse;
- a [platform and governance](../04-platform-and-governance/) foundation;
- a [Product Operations](../05-product-operations/) model for the Run;
- a [learning system](../06-learning-system/) that compounds capability over time.

Buying software will remain the right answer for commodities. Making becomes the right answer, again, for what makes you different — provided you can also run it.
