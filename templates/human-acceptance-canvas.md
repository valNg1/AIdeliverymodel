# Human Acceptance Canvas — Template

> Reusable ADM template. Copy it per commit that reaches human validation. It turns a technical commit into a **clear validation mission**: the Product Owner opens one file and immediately knows *where to go, what to do, what to observe, what to decide, and what happens next.*
>
> **Generated by the [Demo Agent](#demo-agent-contract), not hand-written from the spec.** Inputs: the actual commit, the Test Book, the user-visible behaviour (Demo Pack), and the remaining `HUMAN VALIDATION REQUIRED` items. Do **not** ask the human to re-verify what automated tests already proved — unless a visual or product judgement is still needed.

## What happens next

The Product Owner never has to guess the next action:

| Your decision | What happens |
|---|---|
| **ACCEPT** | The Learning Agent updates the [Living Specification](../03-delivery/intent-based-development.md#living-specification); the capability is considered accepted. |
| **ACCEPT WITH FOLLOW-UP** | This commit is accepted; one or more follow-up issues are created; the Learning Agent records the open items in the Living Specification. |
| **REJECT / FIX REQUIRED** | The feedback goes back to the Delivery Agent; the delivery loop reopens; a new commit is produced; and a new Test Book, Demo Pack, and Human Acceptance Canvas are regenerated. |

## Demo Agent contract

The **Demo Agent** generates this canvas after each commit that reaches validation.

| | |
|---|---|
| **Inputs** | the commit · the Test Book · the user-visible behaviour · the unresolved `HUMAN VALIDATION REQUIRED` items |
| **Outputs** | a Demo Pack · this Human Acceptance Canvas |

**Principles**
- *Every AI-generated commit must end with a clear human validation mission.*
- *The human validates product judgement, not automated testing.*

See the delivery sequence in [Intent-Based Development](../03-delivery/intent-based-development.md#human-acceptance-and-the-demo-agent).
