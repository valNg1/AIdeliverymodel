## What was actually built (from the diff)

- `reuseFeedback(answer, evaluation)` in `src/domain/learning.ts` is a **pure, total mapping** over the existing 3-state `UseEvaluation` (`expression-missing` / `needs-correction` / `valid`) into `{ assessment, correctedSentence, mainCorrections, idiomaticAlternative?, retrySuggested }`.
- It **does not itself classify** error nature. `mainCorrections[].nature` is forwarded from `evaluation.issueTypes`, which comes from **LanguageTool** (a network service) upstream. The specific error type (spelling / grammar / tense / preposition / agreement) is therefore decided by LanguageTool, not by the fix.
- `idiomaticAlternative` is **not produced** — always `undefined` (documented seam; needs a generative model). See [04-gap-analysis](04-gap-analysis.md).
- UI (`LearningSession.tsx`): renders assessment line + plain corrected sentence + retry; submit is **disabled on blank input**; on a LanguageTool error the UI falls back to the deterministic corrector.

This shapes the statuses below: the **mapping** is deterministically testable; the **error-nature accuracy** and **idiomatic quality** are not, and are marked accordingly. Nothing is marked PASS beyond what execution proved.

## 6 — AI reads its own implementation

Comparing **initial intent** → **actual commit `bc32314`** → **test results**:

- **Behaviours correctly implemented:** assessment verdict; plain corrected sentence; `mainCorrections` forwarding; retry affordance; "never invent an error on a valid sentence"; blank-input and empty-issueTypes edges are total and well-formed.
- **Missing behaviour (vs. original prototype):** `idiomaticAlternative` is not produced (always `undefined`) — a known, documented limitation of the LanguageTool engine, not a bug. TC-007 / TC-009's "propose a more natural formulation" is therefore **not delivered**.
- **Unintended behaviour:** none observed. The mapping is pure and total.
- **Regression risk:** low. The change is additive over the existing 3-state contract; all 272 pre-existing tests still pass. The main coupling is that error-nature quality is entirely inherited from LanguageTool.
- **Implementation assumptions:** LanguageTool availability (fallback exists); one primary correction is enough for mobile; issue *nature* is a sufficient explanation for now.
- **Acceptance points still requiring human judgement:** naturalness of any future idiomatic alternative; pedagogical usefulness and tone; mobile readability; whether the result genuinely helps a learner make a better second attempt (the Capability Intent's acceptance signal).
