# Research Backlog

> ⚠️ Product Operations / Run is an **experimental area**. This backlog collects the open questions we are actively trying to answer. It is honest about what is not yet settled.

The purpose of this file is to keep unstable practices visible and improvable, rather than presenting them as finished.

## Open questions

- How should Run cost be estimated during Discovery with acceptable accuracy?
- What is a good default review cadence for supervision matrix rows?
- How do we set AI-output quality thresholds that are meaningful and not arbitrary?
- What is the right division of Run responsibilities between Business, IT, Platform, and a central Run function?
- How much supervision can be automated without eroding human validation?
- How do we detect and respond to drift in AI behavior over time?
- What Run signals most reliably predict a product becoming unhealthy?

## How to use this backlog

- When a Run practice is uncertain, record the question here rather than inventing an answer.
- As practices stabilize, promote them into [run-principles](run-principles.md), [maintenance-model](maintenance-model.md), or [observability-matrix](observability-matrix.md) — and note the change in the [CHANGELOG](../CHANGELOG.md).
- Feed learnings from real Runs back here via [retrospectives](../06-learning-system/retrospectives.md).

*Contributions of field learnings are welcome — see [CONTRIBUTING](../CONTRIBUTING.md). Do not add unobserved metrics.*
