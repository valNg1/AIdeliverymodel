# Standard vs. AI Delivery

A short comparison of the historical delivery model and the AI Delivery Model. This is a first version to be expanded with worked examples in a later release.

| Dimension | Standard model | AI Delivery Model |
|---|---|---|
| Default choice | Buy and integrate | Deliberate build-vs-buy per capability |
| Unit of work | Project (temporary) | Product (durable) |
| Accountability | Dispersed, ends at handoff | Single product owner, end to end |
| Requirements | Captured upfront, then frozen | Continuous design; need connected to Build and Run |
| Team | Humans + external integrators | Human + AI delivery team in defined roles |
| Discovery scope | Functional need | Need + data, architecture, security, cost, and Run impact |
| Knowledge | Often lost at project end | Captured and reused as an asset |
| Run planning | After delivery, often unplanned | Planned during Discovery |
| Strategic asset | The purchased software | The capability to produce, operate, and evolve products |

## Why the difference matters

The standard model is efficient for commodities and predictable integrations. It struggles when the product is strategic, when data and AI behavior must be governed, and when the Run cost is large and was never planned. The AI Delivery Model targets exactly those cases: it makes the full cost visible early and keeps accountability and knowledge inside the organization.
